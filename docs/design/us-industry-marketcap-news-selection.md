# 미국 뉴스 수집 종목 선정 변경 설계

- 작업 브랜치: `ops/us-industry-marketcap-news-selection`
- 기준 브랜치: `ops/do-ssh-deploy-setup-20261017`
- 상태: 설계 기록 완료 / 종목 선정 코드 변경 전

## 목적

뉴스 워커가 미국 전체 거래대금 TOP20을 기준으로 종목을 고르는 현재 방식을 폐기하고, **기존에 정의된 각 업종 안에서 시가총액이 큰 종목을 선정**하도록 변경한다.

## 확정된 요구사항

1. 기존 업종 분류와 업종 그룹을 그대로 사용한다.
2. 종목은 각 업종에 속한 종목만 대상으로 한다.
3. 각 업종 내부 정렬 기준은 시가총액 내림차순이다.
4. 거래대금 순위와 미국 전체 시가총액 TOP20은 사용하지 않는다.
5. 이번 단계에서는 종목 선정 로직만 변경한다.
6. 네이버 뉴스 수집, 뉴스 정규화, AI 분석, R2 저장, 실행 주기, 배치 처리 방식은 변경하지 않는다.

## 재사용할 기존 키움 기능

- 모듈: `backend/providers/kiwoom_us_industries.py`
- 업종 목록: `fetch_us_industry_map()` / `fetch_us_industry_maps()`
- 업종별 시가총액 조회: `fetch_us_industry_stocks(industry_codes, sort="marketcap", ...)`
- 공식 TR: `usa20550`

기존 함수가 이미 업종별 시가총액 순위를 제공하므로 별도 API나 새로운 분류 체계를 만들지 않는다.

## 변경 대상

- `backend/news_worker.py`: 뉴스 대상 종목 목록을 기존 거래대금 TOP20 스냅샷 대신 업종별 시가총액 목록에서 구성하도록 변경한다.
- `backend/services/us_top20_rotation.py`: 기존 고정 TOP20 순환이 새 선정 결과와 맞지 않는 부분이 확인될 때에만 최소 범위로 조정한다. 이번 단계에서 배치 실행 구조 자체는 변경하지 않는다.
- 관련 테스트: 업종별 분류 유지, 시가총액 내림차순, 중복 종목 처리, API 실패 시 잘못된/부분 목록을 새 목록으로 확정하지 않는지 검증한다.

## 이번 단계에서 변경하지 않을 것

- 네이버 뉴스 API 호출 및 검색어
- 뉴스 정규화/중복 제거
- AI 요약·분석
- R2 객체 경로와 저장 형식
- 워커 실행 시간과 회차별 처리량
- 화면 업종 분류 및 UI
- 키움 시세/ETF/실시간 시세 기능

## 구현 전 확인이 필요한 한 가지

뉴스 수집 대상으로 **각 업종에서 몇 종목씩** 뽑을지 확정해야 한다.

참고로 기존 `backend/kiwoom_us_top20_api.py`의 업종별 시가총액 조회 화면은 최대 12개를 요청하지만, 이것이 뉴스 수집 기준으로 확정된 것은 아니다. 사용자가 수량을 확정하기 전에는 임의로 12개를 뉴스 수집 대상으로 고정하지 않는다.

## 완료 검증

- 업종별 목록이 기존 분류와 일치한다.
- 각 업종의 종목이 `market_cap_usd` 내림차순이다.
- 거래대금 TOP20 스냅샷 파일을 뉴스 종목 선정에 사용하지 않는다.
- 업종별 선정 수량이 확정된 규칙과 일치한다.
- 뉴스 수집·AI·R2·스케줄 동작은 변경되지 않는다.
