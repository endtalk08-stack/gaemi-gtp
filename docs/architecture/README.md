# gaemiGTP 구조 기준선 v7

이 문서는 gaemiGTP를 계속 확장하기 위한 구조 기준선이다.

## 목표
- APP SHELL: 화면의 큰 틀
- DATA: 외부 원천 데이터 수집
- CORE: 여러 데이터 소스를 공통 형식으로 맞춤
- ANALYSIS: 원천/공통 데이터를 계산·가공
- API: 프론트엔드에 필요한 결과 전달
- WIDGETS: 사용자에게 보여주는 화면 부품
- BACKTEST: 과거 데이터/전략/실행/결과를 독립 관리
- USER: 로그인, 관심종목, 설정 등
- ADMIN: 데이터/조건/백테스트/콘텐츠 관리

1. 현재 동작하는 v6 계열을 기준본으로 보존한다.

## 뉴스 대표 키워드 기준선

뉴스 키워드의 목표는 키워드 수를 늘리는 것이 아니라, 기사 핵심을 대표 키워드 3개만 읽어도 이해할 수 있게 만드는 것이다.

1. 일반 분류어와 화면 대표 키워드를 분리한다.
   - `공급과잉`, `자금조달`, `매출발표`, `설비투자` 같은 일반어는 내부 분석 증거/fallback으로 유지할 수 있다.
   - 중앙/화면의 최종 대표 키워드는 더 구체적인 합성 키워드를 우선한다.
2. 대표 키워드는 가능하면 `원인 → 상황/우려 → 결과`를 압축한다.
   - 예: `#메모리증설경쟁 #공급과잉우려 #가격하락우려`
   - 실적: `#잠정실적발표 #분기최대실적 #영업이익100조돌파`
   - 수급 뉴스: `#외국인17조매도 #외국인지분율연중최저 #외국인10일연속매도`
3. 숫자는 단독 키워드로 만들지 않는다. 재무항목/주체/행동과 결합한다.
   - `100조` X, `영업이익100조돌파` O
   - `17조` X, `외국인17조매도` O
4. 기사에 없는 해석을 만들지 않는다.
   - 기사에 단순 `공급과잉`만 있으면 임의로 `공급과잉우려`로 확대하지 않는다.
   - `연중최저`를 `역대최저`로 과장하지 않고 기사에 명시된 범위를 보존한다.
5. 종목/회사 엔티티와 재료 키워드는 데이터상 분리한다.
   - 종목 엔티티: 삼성전자, SK하이닉스, TSMC 등
   - 재료 키워드: HBM수요급증, 메모리증설경쟁, 공급과잉우려 등
   - 화면에서는 필요에 따라 함께 표현할 수 있다.
6. 뉴스에서 추출한 수급 표현은 '뉴스 재료'이며 실제 수급 메뉴 데이터를 대체하지 않는다.
7. 우선순위 예:
   - `대규모자금조달 > 자금조달`
   - `영업이익100조돌파 > 매출발표/실적발표`
   - `낸드시장호황 > 반도체/메모리`
   - `생산능력확대 > 투자계획/설비투자`
8. 산업 뉴스에서 이 품질을 먼저 확보한다. 산업 뉴스에서 원하는 대표 키워드가 안정적으로 생성되어야 이후 테마 뉴스/테마주 연결로 확장한다.
9. 새로운 실제 기사 사례에서 대표 키워드가 밋밋하면 일반어를 무작정 삭제하지 말고, 구체 재료 추출 규칙과 최종 대표 3개 선별 우선순위를 개선한다.

### 다른 작업자/GPT가 지켜야 할 사항

- 키워드 사전을 크게 만드는 것 자체를 목표로 하지 않는다.
- 화면에 일반 키워드를 많이 노출하는 방향으로 되돌리지 않는다.
- 기존 뉴스 수집 체계를 화면별로 복제하지 않는다.
- 기사 근거를 벗어난 호재/악재 해석을 합성하지 않는다.
- 산업 뉴스 대표 키워드 품질을 충분히 확보하기 전에 별도 테마주 뉴스 분석 체계를 새로 만들지 않는다.


## DART 공시 상세 복구 봉인

- 기준 상태: 2026-10-04 복구 완료 (`5f406a5` 포함). 국내 DART 공시 상세가 중앙/오른쪽에서 다시 정상 연결된 상태를 보존한다.
- 화면 구조는 `왼쪽 사이드바 ↔ 중앙 채팅 ↔ 오른쪽 패널`을 유지한다. 중앙은 오늘 공시, 오른쪽은 약 1개월 공시를 같은 메뉴별 공시 결과 데이터에서 표현한다.
- DART 상세 파서/연결 경로를 새 generic 파서나 화면별 별도 분석으로 교체하지 않는다.
- `hydrateDartDetails`의 전체 대상 hydration을 임의로 3건 등으로 다시 제한하지 않는다.
- 성능 개선이 필요해도 현재 동작을 먼저 재현·확인하고, 기존 파서/데이터 shape/표현을 보존한 채 병목만 수정한다.
- 공시 파싱 개선은 공시 종류별 실제 사례를 기준으로 필요한 필드만 추가한다. 기존 정상 공시 종류와 중앙/오른쪽 UI/CSS는 건드리지 않는다.
- 과거 코드가 필요하면 전체 롤백하지 말고 정상 동작했던 `4f76a28` 시점을 참고해 공시 관련 조각만 비교한다.

> 경고: 현재 DART 공시 연결은 복구 완료된 기준선이다. 새 기능 작업 중 "정리", "중복 제거", "성능 최적화", "generic 통합"을 이유로 이 경로를 임의 변경하지 말 것. 변경이 꼭 필요하면 현재 동작과 출력부터 검증하고 최소 범위로 수정한다.


## 뉴스 키워드 다음 단계 작업 메모

현재 키워드 엔진은 단순 단어 사전 확장보다 **실제 주가 원인을 설명하는 0~3개의 날카로운 final keyword**를 만드는 방향을 우선한다.

기본 원칙:
- 키워드는 기사에 등장한 중요한 명사가 아니라 **해당 종목에 무슨 일이 발생했는지 압축한 문장 조각**이어야 한다.
- 지표+수치+방향+비교기준, 주체+행동+방향, 사건+결과처럼 의미가 완성된 표현을 우선한다.
- 한 개의 강한 키워드가 세 개의 약한 키워드보다 낫다. final 결과는 0~3개가 정상이다.
- 긍정/부정/중립을 모두 다루되, 단어 하나만으로 호재/악재를 강제 판정하지 않는다.
- title/description의 실제 근거가 없는 키워드는 생성하지 않는다.
- movement_signals는 내부 evidence이며 final keyword로 직접 승격하지 않는다.

### 1. 숫자·변동률 파싱 강화 — 우선 적용 후보

단순 +145%를 호재로 판단하지 않는다. 숫자는 반드시 무엇의 변화인지와 결합한다.

예:
- 영업이익 +145% → #영업이익145%증가
- HBM 매출 60% 이상 증가 → #HBM매출60%이상증가
- 부채 145% 증가는 실적 증가와 동일하게 취급하지 않는다.

향후 파싱 단위는 **지표 + 수치 + 방향 + 비교기준(YoY/QoQ 등)** 이다. 숫자 자체보다 지표의 의미와 변화 방향을 함께 보존한다.

### 2. 네이버 뉴스 검색 정렬 — 비교 실험만

sort=date를 폐기하고 sort=sim으로 교체하지 않는다.

검토 방향:
- 최신성 후보(date)와 관련도 후보(sim)를 비교한다.
- 필요하면 두 후보군을 수집한 뒤 중복 제거/랭킹하는 방식을 실험한다.
- 호재/악재 사전 단어를 AND/OR로 검색 쿼리에 강제로 넣는 방식은 핵심 수집 전략으로 사용하지 않는다. 이미 알고 있는 재료만 수집하는 편향이 생길 수 있다.

### 3. Open DART 정형 재무데이터 — 강한 팩트 레이어 후보

공시 텍스트에서 단어를 찾는 것과 별도로 Open DART의 정형 재무 수치를 활용해 실제 변화를 계산하는 방향을 검토한다.

대상 예: 매출액, 영업이익, 당기순이익, 영업이익률 등 계산 가능한 주요 지표.

단순 이번 분기 > 지난 분기 = 호재로 판정하지 않는다. 가능하면 YoY/QoQ를 구분하고, 향후 컨센서스 데이터가 확보되면 예상 대비 변화도 별도 evidence로 다룬다. 계절성·일회성 항목도 무시하지 않는다.

### 4. LLM은 전체 기사 기본 분석기가 아니라 fallback

모든 뉴스마다 LLM을 호출하지 않는다.

우선순위:
**규칙/완성형 phrase → 숫자·주체·방향 파싱 → DART 등 구조화 팩트 → 문맥 규칙 → 애매한 경우만 LLM fallback**

LLM 후보 조건:
- 관련 evidence는 있으나 final keyword가 0개인 기사
- 긍정/부정 evidence가 충돌하는 기사
- 사전 표현 없이 인과관계가 문장으로만 표현된 기사
- 규칙 기반 신뢰도가 낮은 기사

LLM에는 단순 호재/악재/중립만 요구하지 않고 가능하면 다음 구조를 요구한다.

**대상 종목 → 발생 사건 → 원인 → 핵심 수치 → 방향 → 근거 문장 → 신뢰도**

LLM 결과도 곧바로 화면에 노출하지 않고 **원문 근거 확인 + final keyword gate**를 다시 통과시킨다.

### 5. 뉴스 본문/외부 데이터 확장 원칙

본문 전체가 필요해지더라도 사용자 클릭 시 /analyze hot path에서 기사들을 재수집/재분석하는 구조를 만들지 않는다.

향후 원칙:
**뉴스 수집 → 원천 저장/캐시 → 가공/evidence 추출 → 뉴스 결과 데이터 저장 → 중앙/오른쪽 재사용**

중앙과 오른쪽을 위해 동일 기사를 각각 다시 수집하거나 분석하지 않는다.

BIG KINDS는 뉴스 evidence 확장 후보로만 보관하며 실제 API 제공 필드, 이용조건, 호출 제한을 확인한 뒤 도입 여부를 결정한다.

증권사 API도 뉴스/공시 기능을 있다고 가정하지 않고 각 API의 실제 제공 항목을 확인한 뒤 필요한 역할만 사용한다. 키움은 우선 시세·수급 등 실제 시장 반응 데이터 축으로 본다.

### 6. 장기 evidence 결합 방향

향후 서로 다른 메뉴별 데이터가 같은 사건을 독립적으로 뒷받침하는 경우 키워드의 근거 신뢰도를 높이는 구조를 검토한다.

예:
- 뉴스 #대규모수주
- DART 실제 공급계약 금액/매출 대비 비중
- 키움 거래대금·가격·수급 반응

이는 하나의 공통 결과 데이터로 합치는 의미가 아니다. 뉴스, 공시, 수급/시세는 각각의 메뉴별 결과 데이터를 유지하고, 필요한 분석 단계에서 evidence를 연결한다.

### 다음 작업 순서

현재는 규칙을 무작정 더 추가하기보다 실제 기사 샘플에서 다음 세 가지를 먼저 확인한다.

1. **좋은 키워드** — 그대로 유지할 것
2. **쓰레기/약한 키워드** — final gate에서 제거할 것
3. **놓친 핵심 원인** — 숫자/문맥/조건 조합으로 보완할 것

실제 사례가 충분히 쌓인 뒤 공통 구조를 발견해 자동조합 범위를 넓힌다. 거대한 정규식이나 무차별 사전 확장으로 되돌아가지 않는다.
