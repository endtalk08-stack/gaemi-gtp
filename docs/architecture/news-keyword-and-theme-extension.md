# 뉴스 키워드 로직 및 테마 확장 원칙

이 문서는 gaemiGTP의 현재 뉴스 키워드 방향을 고정하고, 이후 다른 작업자/GPT가 테마 기능을 확장할 때 같은 분석 로직을 중복 구현하지 않도록 하기 위한 기준 문서다.

## 1. 최우선 원칙

화면 구조는 항상 다음을 유지한다.

```
왼쪽 사이드바 ↔ 중앙 채팅 ↔ 오른쪽 패널
```

데이터는 화면별로 다시 만들지 않는다.

```
수집 → 원천 저장 → 가공 → 메뉴별 결과 데이터 → 화면 표현
```

중앙과 오른쪽은 같은 결과 데이터를 서로 다른 형태로 표현할 수 있다. 동일 원천 뉴스를 중앙용/오른쪽용으로 각각 재수집하거나 같은 분석 로직을 복제하지 않는다.

## 2. 현재 종목 뉴스 실행 흐름

현재 종목 분석의 기본 흐름은 다음과 같다.

```
app.py /analyze
 → backend/services/engine.py analyze_stock
 → fetch_stock_news(...)
 → score_stock_news(...)
 → build_connected_keyword_test(...)
 → article_keywords / article_keyword_details 부착
 → build_simple_today_news(...)
 → select_keyword_storyboard_news(...)
 → paired_news_items / storyboard_news_items / keyword_storyboard
 → 중앙/상세 화면
```

뉴스 공급자는 현재 이 흐름에서 Naver News를 사용한다. Google News를 임의로 추가하지 않는다.

## 3. 키워드 엔진의 역할

핵심 함수는 `backend/services/news_scoring.py`의 `build_connected_keyword_test()`이다.

키워드는 두 축을 함께 사용한다.

### A. 공통/정규화 키워드

반복 집계와 검색에 가치가 있고 기사에 명확하게 등장하는 표현을 안정적인 태그로 정규화한다.

예:
- 기업/종목: `#투자확대`, `#공급부족`, `#판매반등`, `#대형수주`, `#유상증자`
- 실적/수익성: `#호실적`, `#어닝서프라이즈`, `#어닝쇼크`, `#수익성개선`, `#수익성악화`, `#마진개선`
- 거시/시장: `#금리상승`, `#금리인하`, `#환율하락`, `#달러강세`, `#CPI둔화`, `#국채금리상승`
- 정책/시장 이벤트: `#트럼프발언`, `#트럼프관세`, `#관세인상`, `#수출규제`, `#증시급락`

공통 키워드는 거대한 수동 사전을 만드는 목적이 아니다. 실제 뉴스에서 반복되고 의미가 안정적이며 향후 검색/집계 가치가 높은 표현만 추가한다.

### B. 발견형 동적 키워드

공통 규칙에 없는 신선한 표현은 제목 기반 fallback으로 발견할 수 있다.

예:
- `#54%급증`
- `#제품확대`

이 동적 로직을 제거하지 않는다. 공통 키워드만 사용하면 새로운 이슈 발견력이 떨어지고, 동적 키워드만 사용하면 장기 집계 데이터가 파편화된다. 따라서 두 방식을 함께 유지한다.

## 4. 키워드 안전 원칙

Naver 제목+description은 기사 전문이 아니므로 문장 조각을 억지로 합쳐 정확한 관계를 추론하지 않는다.

금지 방향:
- 가까이 있다는 이유만으로 명사와 이벤트를 조합
- 기사에 없는 의미를 생성
- `#지난출시`, `#가격출시`, `#통해공급` 같은 구조적 잡음 생성
- 한 화면을 위해 별도 키워드 분석기를 복제

권장 방향:
1. 기사에 명시된 안정적인 phrase rule 우선
2. 없으면 선택 종목이 제목에 명확히 존재할 때 보수적인 동적 fallback
3. 이상한 키워드를 줄이는 것을 키워드 개수를 늘리는 것보다 우선
4. 동적 표현이 여러 뉴스/종목에서 반복되면 공통 키워드 승격 후보로 검토

## 5. 키워드는 장기 데이터 자산

키워드는 오늘 화면에 붙이는 라벨만이 아니다.

향후:
```
뉴스
 → 키워드 발견
 → 공통 키워드 정규화
 → 종목/테마/시장 연결
 → 누적 저장
 → 키워드 빈도·증가율·연관관계
 → 검색/랭킹/조건 탐색
```

예를 들어 `#투자확대`를 누르면 관련 뉴스뿐 아니라 관련 종목과 테마를 연결할 수 있다. 반복되는 키워드는 기간별 빈도와 확산 속도도 계산할 수 있다.

## 6. 테마 적용 방법

중요: **테마 기능을 별도 데이터 결과로 만드는 것**과 **테마 전용 키워드 추출기를 새로 복제하는 것**은 다르다.

테마의 뉴스 선정과 대표성 판단은 종목과 별도로 필요하지만, 뉴스 문장에서 `#수요급증`, `#증설`, `#가격상승` 등을 발견하는 키워드 엔진은 공통으로 재사용한다.

권장 구조:

```
공통 뉴스 수집/가공
        ↓
공통 키워드 추출 엔진
        ↓
 ┌──────────────┬──────────────┬──────────────┐
 종목 뉴스 결과   테마 뉴스 결과   시장 뉴스 결과
        ↓              ↓              ↓
 종목 대표 이슈   테마 대표 이슈   시장 대표 이슈
```

테마 처리의 별도 책임:
1. 테마 정의 및 테마-종목 연결
2. 테마와 관련된 뉴스 후보 선정
3. 특정 종목 하나의 뉴스가 아니라 테마 전체를 대표하는지 판단
4. 공통 키워드 엔진 결과를 테마 단위로 집계
5. 반복도/최신성/관련성을 이용해 테마 대표 키워드 선정

예:
```
HBM 관련 뉴스
 → 공통 키워드 엔진
 → #수요급증 / #공급부족 / #증설 / #가격상승
 → HBM 테마 단위 집계
 → 중앙: 핵심 2~3개
 → 오른쪽: 전체 뉴스/키워드/관련 종목 상세
```

반대 탐색도 가능해야 한다.

```
#공급부족 → 관련 테마 → 관련 종목 → 관련 뉴스
HBM → 현재 키워드 → 관련 뉴스 → 관련 종목
```

## 7. 구현 시 금지 사항

- `theme_news_keyword_extractor.py` 같은 이름으로 기존 키워드 로직을 복사해 별도 엔진을 만들지 않는다.
- 테마 화면을 위해 동일 뉴스를 다시 수집하지 않는다.
- 중앙/오른쪽 각각 별도 키워드 분석을 하지 않는다.
- 기존 동적 fallback을 이유 없이 제거하지 않는다.
- 현재 동작하는 legacy/wrapper를 이름만 보고 삭제하지 않는다.
- 테마 기능 때문에 중앙/왼쪽/오른쪽 UI CSS를 불필요하게 같이 수정하지 않는다.

필요하면 공통 엔진을 작은 재사용 함수로 정리할 수 있지만, 실제 호출 경로와 기존 동작을 확인한 뒤 단계적으로 한다.

## 8. 향후 권장 데이터 형태

구현 시점에 스키마는 실제 저장 구조에 맞춰 결정하되 개념적으로 다음 정보가 있으면 좋다.

```
keyword
normalized_keyword
keyword_type       # common | dynamic
scope              # stock | theme | market
source_news_id
stock_codes[]
theme_ids[]
detected_at
evidence
```

`scope`는 키워드 추출 알고리즘을 분리하기 위한 값이 아니라, 키워드가 어떤 결과 데이터와 연결되었는지 나타내는 메타데이터다.

## 9. 변경 원칙

키워드 로직을 변경할 때는 반드시:
1. 실제 현재 호출 경로 확인
2. 종목 뉴스 결과에 미치는 영향 확인
3. 공통 규칙인지 동적 규칙인지 구분
4. 기존 정상 키워드가 사라지지 않는지 확인
5. 테마/시장 확장 때문에 종목 로직을 복제하지 않았는지 확인
6. 커밋 후 배포와 실제 런타임은 별도로 검증

커밋이 성공했다고 실제 배포/화면 동작까지 검증된 것으로 보고하지 않는다.

핵심 한 줄:

> **종목·테마·시장 데이터의 선정/집계 책임은 각각 가질 수 있지만, 뉴스 문장에서 이슈 키워드를 발견하고 정규화하는 엔진은 공통으로 재사용한다.**
