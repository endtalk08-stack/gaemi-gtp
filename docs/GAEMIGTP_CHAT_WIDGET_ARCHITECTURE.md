# gaemiGTP 패널 → 채팅 → 독립 위젯 구조 기준

> 기준: 2026-10-01 / 사용자와 확정한 구조. 이 문서는 기능을 임의로 재설계하지 않기 위한 구조 기준 기록이다.

## 핵심 구조

원천 API
↓
패널
- 시세
- 수급
- 뉴스
- 공시
- 기타 데이터

↓
패널에서 각 데이터별 분류·가공·저장

↓
채팅창

↓
채팅창 내부에서도 들어온 데이터 종류에 따라 다시 분류

↓
각 데이터 영역을 독립적인 채팅 위젯으로 표시

## 중요한 원칙

1. 채팅창의 위젯은 단순한 AI 답변창이 아니다.
2. 사용자의 질문과 대화가 계속 이어지는 동안 필요한 데이터가 추가로 들어올 수 있다.
3. 채팅 안에서도 데이터 종류별로 독립적으로 분류한다.
4. 시세, 수급, 뉴스, 공시, 이슈, 테마 등은 필요에 따라 각각 독립적인 채팅 위젯으로 표시한다.
5. 패널에서 처리한 데이터와 채팅 내부의 데이터 분류/표시는 서로 다른 단계다.
6. 정상적으로 작동하는 기존 분류 로직을 임의로 삭제하거나 다른 방식으로 합치지 않는다.
7. 원천 API → 패널 데이터 수집/분류/저장 → 채팅 전달 → 채팅 내부 분류 → 독립 위젯 표시의 흐름을 기준으로 한다.
8. 패널 화면을 채팅 데이터 저장소로 취급하지 않는다. 패널의 데이터 결과와 채팅의 위젯 표현을 역할별로 구분한다.

## 예시

사용자: “SK하이닉스 지금 어때?”
→ 시세 관련 채팅 위젯

사용자: “외국인은?”
→ 기존 대화 흐름을 유지하면서 수급 위젯 추가

사용자: “오늘 왜 움직였어?”
→ 뉴스/이슈 관련 위젯 추가

사용자: “관련 공시는?”
→ 공시 위젯 추가

## 뉴스 구조에서 특히 지켜야 할 것

뉴스 원천 데이터가 패널에 들어오면 뉴스 패널에서 필요한 분류·가공을 수행한다.

예:
- 종목
- 실제 기사 근거가 있는 키워드
- 이슈
- 테마
- 움직임 관련 정보

그 결과를 저장하고 채팅에서는 질문에 필요한 결과를 가져와 뉴스/키워드/이슈/테마 등의 독립 위젯으로 표시한다.

뉴스 수집·분류·점수화 로직을 서로 다른 단계에서 중복으로 다시 만들지 않는다.
news_feed.py, news_scoring.py, engine.py, 채팅 위젯 사이의 역할을 확인한 뒤 최소 범위로 수정한다.

## 변경 금지 원칙

이 문서에 기록된 구조를 기준으로 하며, 구조 변경이 필요하면 기존 구조와 충돌하는 부분을 먼저 확인하고 사용자에게 알린다.
