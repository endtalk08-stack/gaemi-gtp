# 2번 자체생산 뉴스 — 격리 실험

**운영에 연결하지 않는 실험.** `main`, Render, DigitalOcean 작업, Neon, 뉴스 화면은 수정하지 않는다. PR·배포·DB 쓰기 없음.

## 목적

기사 원문 **전체**에서 주체·사건·숫자·확정/가능성·후속 내용·배경을 찾아, **기존 기사 제목을 복사하지 않고** 코드만으로 제목과 새 본문을 구성한다. 본문 문장 수는 고정하지 않는다. 원문 사실이 충분히 확인되지 않으면 `not_supported`로 실패 처리한다. 원문 기사 URL과 핵심 태그를 남긴다.

**1번 대체 방식(원문 제목 + 원문 2문장)은 이 실험의 출력이 아니다.** 실험이 충분히 성공하지 못하면 운영에 연결하지 않고 브랜치만 폐기할 수 있다.

## 실행

프로젝트 루트에서:

```bash
python -m unittest discover -s tests -p 'test_full_article_news_experiment.py' -v

# 원문 전체가 들어 있는 UTF-8 텍스트 파일
python -m experiments.full_article_news --file article.txt

# 실제 언론사 기사 HTML (원문을 확보할 수 있을 때만)
python -m experiments.full_article_news --url 'https://example.org/news/article'
```

출력: `status: experimental`이면 실험 결과(제목·새 본문·태그·원문 URL). `not_supported`이면 품질/확인 실패로 보류. 어떤 경우든 **게시하지 않는다.**

기존 운영용 기사 리더는 본문을 **5,000자까지 잘라 읽는다**. 실험 리더는 JSON-LD 원문 또는 기사 본문 영역의 **전체 내용(최대 60,000자)을 검사**한다. 페이지가 크거나 본문을 식별하지 못하면 실패 처리한다. 제공사가 본문 일부만 노출하는지는 자동으로 보장할 수 없으므로 사람이 확인해야 한다.

## 평가 기준

20~30건의 서로 다른 기사(기업 투자·계약·사업·실적·임상·시장 전망)에서 확인한다.

- 제목이 기사 원문 제목을 그대로 복사한 것인가? 아니어야 함.
- 회사 주체가 뒤바뀌거나 제3자 회사를 주인공으로 삼았는가? 0건이어야 함.
- 숫자·단위·확정/예상 여부가 원문과 일치하는가? 오류 0건이어야 함.
- 기사 **후반부** 핵심 사실도 반영했는가?
- 새 본문이 어색한 원문 문장 이어붙이기인가? 그러면 실패.
- 중요한 사실 누락, 원문 일부 접근 불가, 재구성 불가 비율을 기록.

현재는 **투자 가능성·사이버트럭을 활용한 사업 확대·임상 3상** 3가지 규칙에 대한 초기 실험이다. 다른 사건은 성공한 척하지 않고 거절한다. 결과를 실제 언론 뉴스 수준이라고 판단하거나 자동 운영에 적용하면 안 된다.

## 원문 출처

실제 기사를 테스트할 때 게시사의 접근 정책과 이용권한을 지킨다. 출처 링크는 항상 남기고, 검증·평가용으로만 사용한다. 저작권 있는 기사 본문 전체를 DB나 프런트엔드에 저장/전송하지 않는다.
