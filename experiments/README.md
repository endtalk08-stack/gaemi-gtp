# 자체생산 뉴스 2번 — 테스트 브랜치 전략·인수인계

**기준 기록: 2026-10-25 / 브랜치: experiment/full-article-news-20261025**

이 파일이 실험을 중단했다가 이어갈 때의 **기준 문서**다. 다음 작업자는 이전 대화를 몰라도 여기서 상태·결정·다음 단계·실행법을 확인할 수 있어야 한다.

**격리 원칙:** main, Render, DigitalOcean 작업, Neon DB, 운영 뉴스 화면은 수정하지 않는다. PR·배포·DB 쓰기·자동 게시 없음. 실험이 실패하면 이 브랜치만 삭제한다.

## 확정한 두 가지 방법

- **2번 (우선 실험, 자체생산)**: 뉴스 목록을 모은 뒤 분류·필터로 선정된 기사 **원문 전체만** 읽는다. 사실·숫자·주체·배경·진행 상황을 재구성해 **자체 제목 + 자체 본문**을 작성한다. **본문 2문장 제한 없음.** 길이는 실제 내용의 중요도에 따른다. 원문 제목 복사 또는 원문 앞 2~3문장 이어붙이기는 자체생산이 아니다. 기사 출처 링크와 원문에서 추출한 핵심 태그를 유지하고, 태그를 왼쪽 사이드바에서 활용하는 방향으로 설계한다.
- **1번 (2번 실패 시 검토할 대체 방식)**: **원문 제목 그대로 + 원문 핵심 2문장**(기존 3문장에서 변경) + 원문 기사 링크 + 원문 핵심어/사이드바 태그. 원문 2문장의 사용 권한을 확인한다. 원문 일부라도 읽을 수 없다면 임의로 2문장을 만들지 않으며, 원문 제목과 링크만 보류 상태로 둔다.
- **전환 시점**: 2번이 사실 정확성과 자연스러움 테스트를 통과하지 못하면 운영에 적용하지 않는다. 1번 전환 여부는 검증 결과를 보고 판단한다.

## 개정된 뉴스 처리 전략

**정답: 수집 → 7개 유형 분류 → 후보 걸러내기 → 선정된 기사만 원문 전체 읽기 → 유형별 자체생산 → 원문 대조 검증 → 결과 기록.**

1. **메타데이터 수집**: 각 기사의 제목, 짧은 설명, 링크, 언론사, 발행시각, 가능하면 대상 종목/티커만 확보한다. **이 시점에 모든 원문을 열지 않는다.**
2. **유형별 1차 분류**: 아래 7가지 중 주유형 하나, 필요하면 보조 유형을 기록한다. 제목·설명으로 판단한 분류는 잠정값이다.
3. **1차 필터링**: 시간, 중복 URL/기사, 링크 유효성, 종목·시장 관련성, 출처, 유형별 우선순위, 읽을 원문 수를 판단해 후보를 선정한다. 처음부터 너무 좁게 걸러 중요한 기사를 누락하지 않도록 통계를 남긴다.
4. **원문 전체 읽기**: **선정된 URL만** 읽는다. 기사 JSON-LD 또는 본문 영역을 확인하고 후반부까지 본다. 접근 불가·로그인·일부 공개·광고/페이지 본문 오인 가능성이 있으면 불완전 판정한다. 원문을 읽은 후에는 기업 주체·기사 분류를 다시 확인하고 부적합 기사는 제외한다.
5. **유형별 사실 추출과 기사 재구성**: 7개 유형 각각 다른 항목을 추출한다. 뉴스 내용을 인위적으로 2문장으로 제한하지 않고 중요 사실에 맞춰 새 제목·문단을 구성한다.
6. **검증**: 수치·통화·단위·일정·기업 주체·확정/예정/분석·부정 표현·인과 관계·원문 근거를 비교한다. 원문에 없는 내용을 만들거나 문장 복사로 위장하면 실패. 링크·핵심 태그를 포함한다.
7. **실험 결과 기록**: 성공·보류·실패와 사유, 분류 및 기사별 품질을 남긴다. 어떤 경우에도 현재 실험 결과를 사이트에 자동 게시하지 않는다.

**현재 운영 코드 참고:** backend/services/news_result.py에도 후보 선별 → read_selected_article_details → 원문 후 재검증 흐름이 이미 있다. 재사용 가능성을 살피되 운영 코드 수정 금지. 운영 원문 리더 backend/services/news_detail.py는 5,000자 제한이 있고, 실험 리더는 최대 60,000자를 읽게 설계했다. 60,000자까지 읽는 것과 게시사 기사 **원문 전체를 실제로 확보한 것**은 다르다. 실기사 대조 검증 필요.

## 7가지 뉴스 유형별 서로 다른 작성 전략

| 분류 | 원문에서 확인할 핵심 사실 | 자체 기사 구성 |
| --- | --- | --- |
| **미국 증시 마감** | 마감 거래일, 다우·S&P500·나스닥 종가/등락률, 주요 업종, 확인된 하락·상승 배경 | 시장 전체 마감 결과 → 지수별 변화 → 업종·종목 반응 → 관전점(확인 시) |
| **개별 종목** | 실제 행위 주체, 계약·투자·제품·규제 등 사건, 상대 기업, 규모·일정, 확정 여부 | 누가 무엇을 했나 → 조건·규모 → 배경 → 확인된 영향 |
| **경제지표** | 발표 기관·대상 기간, 발표치·예상치·이전치, 단위·수정치, 발표 시각 | 실제 발표 수치 → 예상·이전과 비교 → 의미(원문 근거가 있을 때만) |
| **에너지** | WTI/브렌트/가스 종류, 가격 단위, 거래일, 재고·감산·생산·수요, 지정학적 요인 | 가격/정책 사건 → 공급·수요 사실 → 영향을 줄 조건 |
| **연준 일정** | 회의·연설·금리 발표 시점, 미국 현지시간/한국시간, 확정된 일정과 미결정 정책 구분 | 언제 어떤 행사가 있는가 → 확인된 예정 내용 → 시장이 볼 변수 |
| **투자의견** | 증권사, 분석 종목, 기존/새 목표주가와 통화, 등급 유지/상향/하향, 날짜·근거 | 어떤 기관이 무엇을 변경 → 전후 수치 → 평가 근거 |
| **실적 발표** | 회계분기, 매출·EPS, 예상치·전년 대비, GAAP 여부, 회사 가이던스 | 실적 결과 → 시장 기대와 비교 → 사업부 변화 → 가이던스 |

**복합 기사:** 주된 사건을 기준으로 하나만 원문을 열고, 다른 분류는 보조로 표시한다. 단순히 회사가 언급됐다고 그 회사가 행동 주체라고 확정하지 않는다. 제목에 나타난 숫자도 원문 전체에서 다시 검증한다.

## 이어서 실험하는 방법

프로젝트 루트에서 테스트 브랜치를 체크아웃한다.

~~~bash
git switch experiment/full-article-news-20261025
python -m unittest discover -s tests -p 'test_news_selection_experiment.py' -v
python -m unittest discover -s tests -p 'test_full_article_news_experiment.py' -v
~~~

현재 뉴스 목록의 메타데이터만 담긴 JSON 리스트를 만든다. **원문 전체를 JSON에 넣지 않는다.**

~~~json
[
  {
    "title": "뉴욕증시 주요 지수 하락 마감",
    "description": "뉴욕 시장 마감에 관한 개요",
    "url": "https://publisher.example/article",
    "published_at": "2026-10-25T00:00:00Z",
    "source": "기사 출처",
    "stock_name": ""
  }
]
~~~

~~~bash
# 후보 분류·필터링만 실행. 기사 원문 읽기 없음.
python -m experiments.news_selection --file candidates.json

# 선별된 기사 URL만 읽고 자체생산 시도. 결과는 로컬 출력뿐.
python -m experiments.news_selection --file candidates.json --read-selected

# 기존 단일 원문 실험(선별 단계 우회하는 디버깅용, 실전 경로 아님)
python -m experiments.full_article_news --file saved_full_article.txt
~~~

**실험 가정:** 기본 메타데이터 발행일 필터 48시간, 유형당 3건, 총 21건. 운영 기준으로 확정한 값이 아니며 실제 기사 데이터로 검토해야 한다. 연준 **미래 일정**은 기사 발행일과 행사일이 다르므로 유형별 별도 일정/보관 규칙이 필요하다.

## 평가 기준과 다음 작업 순서

1. 먼저 두 테스트를 실행하고 **성공/실패 로그**를 남긴다. 현재는 실행 로그가 없다.
2. **7유형 × 3~5건 = 21~35건**의 실기사 메타데이터를 모아 분류 정확도와 놓친 주요 기사를 기록한다.
3. 선별된 기사만 원문을 읽고 **전문 확보 여부 및 기사 주체/유형 재판정**을 기록한다.
4. 우선순위대로 7유형별 서로 다른 사실 추출기·본문 작성기를 확장한다. 기본 글자 수를 정해 자르지 않는다.
5. 원문 근거가 없는 수치·주체·날짜·예정/확정·인과 오류는 **0건 목표**로 사람이 대조한다. 후반부 핵심 사실 반영, 본문 자연스러움, 거절률, 읽기 비용도 함께 기록한다.
6. 태그는 **선별 제목뿐 아니라 선정된 원문 핵심어**를 이용하게 고도화하고, 사이드바 연결은 별도 검증 후 판단한다.
7. 정확성·커버리지·문장 품질이 만족스럽지 않으면 2번을 운영에 적용하지 않는다. 필요하면 1번으로 전환하거나 테스트 브랜치를 폐기한다.

## 금지 사항 / 실험 종료 조건

- 기사 수집 직후 **전 기사 원문 일괄 수집 금지**.
- 원문 제목 붙여넣기, 중요 숫자 추측, 전망의 확정 사실화 금지.
- 임상/실적/경제지표는 결과와 예상치·검증된 기간 구분. 연준은 예정/결정 구분.
- 저작권·게시사 접근 조건을 준수한다. 테스트 용도 외 기사 전문 저장/배포 금지.
- **main 병합, PR, 운영 배포, DB 수정은 별도 결정 전 금지.**
- 실패한 테스트를 성공으로 기록하거나 테스트 파일만 존재하는 것을 검증 완료로 표시하지 않는다.

- 선별: **7건 → 5건 선택**. 유형별 최대 3건 및 최신순으로 2건 제외. **선별 정확도는 미검증**이며, 최신순 제한으로 중요한 기사를 놓칠 가능성(테슬라/퍼플마인 뉴스 미선정 등)이 드러났다.
- 원문 읽기: 선정 5건 중 **4건 본문 텍스트 추출**(2,884자 / 2,535자 / 1,770자 / 1,046자). 나머지 **1건 확보 실패**(아마존/eDaily). 추출 텍스트가 언론사 원문 전체인지까지는 검증하지 않았다.
- 자체생산: **성공 0건 / 불충분·미지원으로 보류 4건 / 원문 확보 실패 1건**. 모더나 임상, 스페이스X 컴퓨팅 수요, 팔란티어 목표주가, 유가/뉴욕 마감 기사는 모두 현재 3종 작성 규칙과 맞지 않아 unsupported_or_ambiguous_article 상태로 보류됐다.
- **DB 쓰기/운영 게시/배포 없음.** GitHub Actions 작업 로그에 실험 결과만 출력했다.

**중요한 해석:** 메타데이터 → 분류·선별 → **선정된 원문 URL만 읽기**의 실행 흐름은 실제 기사 URL에서도 작동했지만, **이번 표본에서 자체 기사 작성 성공률은 0%**다. 7가지 유형별 작성기는 아직 구현되지 않았다. GitHub Actions의 초록색 성공은 명령이 정상 종료됐다는 뜻이지 기사 품질 성공을 뜻하지 않는다.

**다음 작업 우선순위**
1. 최신순으로 유형별 3개만 자르는 대신 **주요성·사건 다양성·회사 주체 관련성**으로 후보를 선별하고 누락을 확인한다.
2. 7개 유형별 원문 사실 추출기와 새 제목·본문 구성 규칙을 독립적으로 확장한다. 사건·숫자·인과를 임의로 생성하지 않는다.
3. 출처별로 원문 전체 확보 여부 및 광고/댓글/연관기사 혼입, 접근 실패 이유를 분리 진단한다.
4. 같은 기사 목록으로 다시 검증해 실제 작성 성공률과 사실 오류를 기록한다. **자동 운영 연결은 계속 금지.**
